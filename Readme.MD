# LoggerMixin

Лёгкая библиотека для логирования в Python с поддержкой ротации файлов и настройки уровня логирования через переменные окружения.

Позволяет подключить логгер к любому классу через наследование.

## История изменений

### 1.1.0 — 2026-10-13

- Добавлен параметр `name_by_date=True` для формирования имени основного логгера по текущей дате и времени UTC. Он не может использоваться одновременно с `logger_name`.
- Добавлен метод `append_stream_logger(name)` для подключения дополнительного именованного логгера с выводом в консоль. Он использует `LOG_LEVEL` и общий формат сообщений; при наличии обработчиков новые не добавляются.
- Добавлен словарь `_additional_logger` для хранения дополнительных логгеров. Оба метода сохраняют логгер в словарь; повторный вызов любого из них с уже зарегистрированным именем пропускается.
- Добавлены публичные свойства `logger` для доступа к основному логгеру и `additional_logger` для получения дополнительных логгеров по имени.
- Добавлен метод `append_file_logger(name)` для подключения дополнительного именованного логгера с записью в `LOG_DIR/<имя_класса>/<имя_логгера>.log` и ротацией (10 МБ, 5 резервных файлов, UTF-8). Он использует `LOG_LEVEL` и общий формат сообщений; при наличии обработчиков новые не добавляются. Символы `/` и `\` в имени файла заменяются на `_`.
- Изменён путь файлов основного логгера: вместо `LOG_DIR/<имя_логгера>.log` используется `LOG_DIR/<имя_класса>/<имя_логгера>.log`. При обновлении следует учитывать новый путь; существующие файлы автоматически не переносятся.

## Установка

**Требования:** Python 3.11+, `pip` и Git, доступный в `PATH`.

### Установка напрямую из GitHub

Установите библиотеку из ветки `main` в выбранное Python-окружение:

```bash
python -m pip install "git+https://github.com/SameUsers/LoggerMixin.git@main"
```

Или добавьте в `requirements.txt`:

```text
git+https://github.com/SameUsers/LoggerMixin.git@main
```

Затем установите зависимости:

```bash
python -m pip install -r requirements.txt
```

Для установки конкретного состояния кода замените `main` после `@` на имя существующего тега или полный хеш коммита в удалённом репозитории.

### Обновление из GitHub

Чтобы установить актуальный код из `main`, в том числе если версия пакета не изменилась:

```bash
python -m pip install --upgrade --force-reinstall "git+https://github.com/SameUsers/LoggerMixin.git@main"
```

### Установка из локального клона

```bash
git clone https://github.com/SameUsers/LoggerMixin.git
cd LoggerMixin
python -m pip install .
```

Для разработки используйте `python -m pip install -e .` вместо обычной установки: изменения исходного кода будут доступны без переустановки пакета.

Проверка установки:

```bash
python -c "from logger_mixin import LoggerMixin; print('LoggerMixin installed successfully')"
```

## Использование

```python
from logger_mixin import LoggerMixin


class Test(LoggerMixin):
    def __init__(self) -> None:
        super().__init__(logger_name="MyCustomLogger")

    def test(self) -> None:
        self.logger.info("Информационное сообщение")
        self.logger.warning("Предупреждение")
        self.logger.error("Ошибка")


test = Test()
test.test()
```

### Доступ к основному логгеру

Свойство `logger` возвращает основной объект `logging.Logger`. Внутри класса обращайтесь через `self.logger`, а снаружи — через свойство экземпляра:

```python
test.logger.info("Сообщение от основного логгера")
test.logger.warning("Предупреждение")
test.logger.error("Ошибка")
```

Основной логгер выводит сообщения в консоль и файл, если при инициализации у него ещё не было обработчиков. Свойство не имеет setter: присвоить ему другой логгер нельзя, но методы возвращённого объекта доступны.

### Автоматическое имя логгера

Если не передавать `logger_name`, имя будет сформировано автоматически на основе модуля и названия класса.

```python
from logger_mixin import LoggerMixin


class Test(LoggerMixin):
    def __init__(self) -> None:
        super().__init__()
```

### Переопределение имени логгера

```python
super().__init__(logger_name="CustomLogger")
```

### Имя логгера по дате

Для формирования имени по текущей дате и времени UTC передайте `name_by_date=True`:

```python
super().__init__(name_by_date=True)
```

Формат имени — `YYYY-MM-DD_HH-MM-SS_ffffff`, где `ffffff` — микросекунды. Например, для класса `Test` файл будет создан по пути `logs/Test/2026-10-13_12-30-45_123456.log`. Имя задаётся при создании экземпляра и не меняется при наступлении следующего дня.

Параметры `logger_name` и `name_by_date=True` являются взаимоисключающими: их совместное использование вызывает `RuntimeError`. По умолчанию `name_by_date=False`.

### Дополнительные логгеры

Методы `append_stream_logger(name)` и `append_file_logger(name)` подключают именованные логгеры для вывода в консоль и записи в файл соответственно. Они возвращают `None`; зарегистрированный логгер можно получить через словарь `additional_logger` по тому же имени:

```python
from logger_mixin import LoggerMixin


class Service(LoggerMixin):
    def __init__(self) -> None:
        super().__init__()
        self.append_stream_logger("service.console")
        self.append_file_logger("service.audit")

    def run(self) -> None:
        self.logger.info("Запуск операции")
        self.additional_logger["service.console"].info("Сервис запущен")
        self.additional_logger["service.audit"].info("Операция выполнена")


service = Service()
service.run()

audit_logger = service.additional_logger["service.audit"]
audit_logger.warning("Сообщение от дополнительного логгера")
```

Обращение к незарегистрированному имени через `additional_logger[name]` вызывает `KeyError`. Для необязательного логгера используйте `.get()`:

```python
audit_logger = service.additional_logger.get("service.audit")
if audit_logger is not None:
    audit_logger.info("Дополнительный логгер доступен")
```

Свойство `additional_logger` возвращает исходный словарь, а не копию. Для регистрации используйте методы `append_stream_logger()` и `append_file_logger()`, чтобы сохранить настройку обработчиков.

Файловый логгер из примера пишет в `LOG_DIR/Service/service.audit.log`. Дополнительные логгеры используют `LOG_LEVEL` и общий формат сообщений. Они работают независимо от основного логгера: сообщения в них нужно отправлять явно.

Повторная регистрация одного имени в экземпляре пропускается, в том числе при вызове другого метода. Для отдельных консольного и файлового логгеров используйте разные имена. Если у именованного логгера уже есть обработчики, методы сохраняют их и не добавляют новые. Именованные логгеры общие для всего процесса, поскольку создаются через `logging.getLogger(name)`.

## Конфигурация

Настройка осуществляется через переменные окружения.

| Переменная | Описание | Значение по умолчанию |
|---|---|---|
| `LOG_DIR` | Директория хранения логов | `logs` |
| `LOG_LEVEL` | Уровень логирования | `DEBUG` |

Пример `.env`:

```dotenv
LOG_DIR=logs
LOG_LEVEL=DEBUG
```

Переменные окружения должны быть загружены до импорта библиотеки и определения классов-наследников: настройки считываются при создании классов. Библиотека не загружает `.env` автоматически. Неизвестное значение `LOG_LEVEL` вызывает `ValueError`.

## Возможности

- Подключение через наследование `LoggerMixin`.
- Автоматическое создание логгера для класса.
- Возможность задать собственное имя логгера.
- Логирование в консоль и файл.
- Ротация лог-файлов.
- Настройка уровня логирования.
- Использование стандартного модуля `logging`.

## Ротация логов

По умолчанию используется `RotatingFileHandler`:

- Максимальный размер файла — 10 МБ.
- Количество резервных файлов — 5.
